# Golden tests

`golden_tests.py` is the regression guard: the QA engine must keep **passing**
known-good work and keep **failing** known-bad synthetic cases. Run it after
any change to `lib/` or `config/`:

```bash
cd creative-os
python3 tests/golden_tests.py
```

## Fixture tiers

| Tier | Location | In public repo? | Why |
|---|---|---|---|
| **Private goldens** | `../facebook/week1/` (maintainer's workspace) | No | Real delivered production artwork for a live personal brand. It is kept out of the public repo deliberately — it is client/brand work, not engine code, and publishing it is neither needed for correctness nor appropriate. |
| **Synthetic goldens** | `tests/fixtures/synthetic/` | **Yes** | Deterministic known-good canvases generated from the public `config/brand.config.example.json`, so every clone runs the full golden shape — including the "known-good must pass" direction. |

In a fresh clone you will see two `SKIP` lines for the private tier and
**12/12 passed**. In the maintainer's workspace, both tiers run: **18/18**.
A `SKIP` is informational; a missing `tests/fixtures/synthetic/` directory is
a **FAIL** (the fixtures are committed and must be present).

## Synthetic fixtures

Generated by `make_synthetic_goldens.py` — pure geometry, no text glyphs, so
output does not depend on fonts or freetype versions:

- `good-post-01/02.png` — valid 1080×1350 canvases: flat brand background
  (clean corners for QA03a), content blocks inside margins.
- `seq/slide-01..04.png` — a 4-slide series whose counter chip is locked at
  the same position/size on every slide (QA26) with constant inner ink-height
  (QA27), while slide content legitimately varies.

They are committed to the repo. Re-run the generator **only** if the fixture
spec changes, then re-commit the output together with any test changes. The
series boxes (`SYN_BOX`, `SYN_TEXT_BOX`) are a contract shared between the
generator and `golden_tests.py` — change them in both places or not at all.
